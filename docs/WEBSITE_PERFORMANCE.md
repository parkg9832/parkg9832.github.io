# 홈페이지 성능 운영 기준

2026-10-12 적용. 대상은 실제 공개되는 한국어·스페인어·영어 48개 정적 페이지와 공통 스크립트, 스타일, 미디어다. Next.js 개발 폴더가 있다는 이유로 방문자에게 Next.js 전체가 전송된다고 판단하지 않는다. 생성된 HTML에서 참조하는 파일을 기준으로 측정한다.

## 로딩과 코드 관리

- 닫힌 상담창은 실행 버튼만 준비한다. 회사 지식·FAQ·대화 분류·AI 연결·상담 UI의 여섯 파일은 상담창을 처음 열 때 순서대로 한 번만 불러온다. 버전 해시는 생성기가 관리한다. 세션에서 열려 있던 상담창은 복원할 수 있다. 로딩 실패에는 문의 페이지를 안내하며 개인정보를 보내지 않는다.
- `scripts/prerender-content.mjs`가 생성한 본문에는 `data-content-language`를 기록한다. 홈·브랜드 소개·제품 목록·FAQ는 현재 언어와 일치하는 본문을 다시 만들지 않고 언어 버튼과 기존 동작을 연결한다. 푸터도 `data-footer-language`가 일치하면 다시 만들지 않는다. HTML만으로 읽을 수 있는 내용과 이미지 노드를 유지한다.
- 원본 루트 페이지의 언어 렌더링과 로컬 체험단 미리보기는 유지한다. 언어 전환은 해당 언어의 페이지로 이동한다. 뉴스 검색·페이지 이동·사진 확대·영상 재생·갤러리 조작·모션은 기존 이벤트 연결을 유지한다.
- 화면 아래의 홈 제품 사진은 `loading="lazy"`, `decoding="async"`로 출력한다. 첫 화면이 아닌 사진에 높은 요청 우선순위를 주지 않는다. 생성용 DOM에서도 속성이 HTML에 남도록 `setAttribute`로 설정한다.
- 128px 전문가 프로필에는 160px/320px WebP와 `sizes="128px"`를 사용한다. 원본 사진을 보존하며 화면에 필요한 해상도를 제공한다.
- 뉴스 목록·홈의 작은 소식 카드·행사 갤러리의 작은 사진에는 기존 640px WebP를 사용한다. 기사 메인 사진과 확대창은 기존 큰 사진을 사용한다. 영상은 명시적으로 재생하기 전 다운로드하지 않는다.
- 현재의 스타일 적용 순서와 타이포그래피·모션 규정은 유지한다. 사용 여부와 시각 검증 없이 CSS나 원본 자산을 일괄 삭제하지 않는다. 사용하지 않는 Black Han Sans 요청은 제거하고 지정된 Archivo Black·Bebas Neue·Noto Sans·Noto Sans KR를 유지한다.

## 점검 명령과 측정 범위

```powershell
npm run generate:i18n
npm run test:performance
npm run audit:performance
```

회귀 검사는 48개 공개 페이지에서 생성된 제목과 주요 콘텐츠·사진·푸터의 노드가 런타임 연결 후 유지되는지 확인한다. 닫힌 상담의 지연 로딩, 작은 이미지 파일, 홈 제품 사진의 lazy 속성, 로컬 리뷰 미리보기와 종료된 캠페인 리다이렉트도 검사한다. 뉴스·상담·내비게이션·SEO·보안·폼 검사는 별도 해당 프로젝트 명령으로 수행한다.

감사 결과는 공개 배포에서 제외되는 `output/performance/after.json`에 저장한다. `scriptBytes`는 HTML에 처음 연결된 같은 출처의 JS 파일 합계, `scriptGzipBytes`는 파일별 gzip 합계다. `allImageBytes`는 기본 `img src`의 중복을 제거한 파일 합계이며 `eagerImageBytes`는 lazy가 아닌 파일만 합산한다. 상담의 여섯 파일은 `deferredChatBytes`로 따로 측정한다. 외부 폰트·분석 서비스, 이미지 srcset 선택, 캐시 및 네트워크 시간은 이 수치에 포함되지 않는다. 파일 감소율을 실제 로딩 시간 감소율로 표현하지 않는다.

## 2026-10-12 변경 결과

변경 전 로컬 48개 생성 페이지와 변경 후의 정적 참조를 비교했다. 한국어 대표 페이지 기준이며 동일한 로딩 정책이 세 언어에 적용된다. 이후 코드가 바뀌면 감사 명령의 현재 수치를 우선한다.

| 페이지 | 처음 연결된 JS 원본 바이트: 전 → 후 | 감소 |
|---|---:|---:|
| 홈 | 300,337 → 186,545 | 37.9% |
| 브랜드 소개 | 188,095 → 73,533 | 60.9% |
| 제품 목록 | 179,823 → 65,203 | 63.7% |
| K-PEÑO·Para Carnes 상세 | 185,486 → 70,737 | 61.9% |
| FAQ | 183,186 → 68,590 | 62.6% |
| 문의 | 187,849 → 73,100 | 61.1% |
| 뉴스 목록·기사 | 243,783 → 129,343 | 46.9% |

홈의 처음 연결된 JS를 파일별 gzip으로 비교하면 93,384 → 54,562바이트다. 상담의 여섯 파일 120,165바이트(파일별 gzip 41,311바이트)는 상담창을 열 때 추가로 로드한다.

홈의 기본 이미지 참조 합계는 2,604,132 → 828,563바이트(68.2% 감소), 뉴스 목록은 1,677,000 → 374,414바이트(77.7% 감소)다. 홈에서 lazy가 아닌 기본 이미지 참조는 313,450 → 21,600바이트로 줄었다. 1,525,939바이트의 원본 프로필은 160px 2,248바이트·320px 5,674바이트로 출력한다. 사진의 원본, 갤러리 확대 및 기사 메인 이미지는 보존했다.

정적 파일 검사와 DOM 회귀 검사는 실제 브라우저의 성능 측정과 다르다. 이 수치만으로 실제 다운로드 시간이나 LCP·INP·CLS를 주장하지 않는다.

별도로 실제 Chrome에서 48개 페이지를 390·768·1440px로 열어 144개 조합의 제목·언어·가로 넘침·런타임 예외·닫힌 상담의 요청 여부를 확인했다. 가로 넘침과 런타임 예외는 없었고, 닫힌 상담의 여섯 파일 요청은 0건이었다. 상담을 열면 여섯 파일을 가져오고 모바일 전체 화면과 데스크톱 패널로 전환했다. 선택 안내와 연락 버튼 조건을 유지한다. 기록은 로컬 `output/playwright/refactor/`에 보관한다.

GitHub의 `Website checks`는 생성·타입·빌드·기능·보안·성능·운영 의존성 검사를 실행한다. Pages의 게시 작업과 별도이므로 이 검사를 Pages 배포 차단 장치로 설명하지 않는다.
