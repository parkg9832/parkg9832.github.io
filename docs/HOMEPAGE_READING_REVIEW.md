# 스크롤 중심 홈페이지 검토 · 2026-09-11

## 발주자와 소비자의 판단 기준

제품과 용도는 첫 방문에서 발견되어야 한다. 설명을 읽기 위해 전환 버튼을 누르게 하지 않는다. 링크는 더 자세한 정보 또는 참여·문의라는 목적지가 있을 때 남긴다. 브랜드 색·서체·검수 본문·제품 이미지는 이어 쓴다.

| 기존 요소 | 최종 처리 | 방문자에게 생기는 변화 |
|---|---|---|
| 한국을 먹다 장식 배지, 전체 움직임 정지 | 제거 | 의미를 해석하거나 동작을 관리할 필요가 없다 |
| 모바일 제품 탭 | 두 제품을 세로로 배치 | 다른 제품을 놓치지 않는다 |
| 음식 페어링 탭과 반복 상세 링크 | 세 장의 사진과 용도를 함께 표시 | 무엇에 먹는지 바로 비교한다 |
| 현장 사진·추천사·기관 로고 넘김 | 사진 모음·전문·로고를 펼침 | 신뢰 근거를 기다리거나 넘기지 않는다 |
| 응원 메시지 자동 이동 | 여섯 카드 정적 배치 | 읽던 글이 움직이지 않는다 |
| FAQ 펼치기 | 세 답변 상시 노출 | 짧은 기본 정보를 바로 읽는다 |
| 중복 출시 안내와 제품 전체 보기 | 제거 | 비슷한 이동을 반복해서 권하지 않는다 |
| 제품 상세 사진 전환 | 병과 음식 사진 함께 표시 | 포장과 사용 장면을 함께 이해한다 |
| 응원 CTA | 응원하기 → 입력 폼 | 버튼 이름과 도착 후 행동이 일치한다 |

유지한 목적지: 첫 화면에서 제품으로 이동, 각 제품 상세, 브랜드 연혁, 응원 폼, 전체 Q&A, 사업 문의, 언어·메뉴·SNS. 상세 페이지와 폼에서 필요한 선택·제출 기능은 유지한다.

## 공식 F&B 사이트에서 검토한 구성

공식 페이지의 콘텐츠와 탐색 구조를 읽고 비교했다. 아래의 적용 여부는 MOKDA에 대한 디자인 판단이다. 해당 사이트 전체를 모바일·데스크톱으로 시각 검수했다는 뜻은 아니다.

| 참고 | 검토한 요소 | MOKDA 적용 판단 |
|---|---|---|
| [Graza](https://www.graza.co/) | 제품별 소개와 생산자 이야기 | 제품을 먼저 보여주고 뒤에 근거를 배치 |
| [Fly By Jing](https://flybyjing.com/) | 제품·브랜드 이야기·레시피 | 음식 활용과 브랜드 이야기를 이어 읽도록 구성 |
| [Diaspora Co.](https://www.diasporaco.com/) | 레시피 이미지와 생산자 이야기 | 음식 사진과 실제 현장 사진의 역할 구분 |
| [Brightland](https://brightland.co/) | 제품군·사용법·이야기 목적지 | 비슷한 링크 반복보다 문맥에 맞는 상세 이동 |
| [Momofuku](https://www.momofuku.com/) | 위치·예약·소개별 다른 행동 | 버튼마다 구체적인 목적지가 있어야 한다는 기준 |
| [TRUFF](https://www.truff.com/) | 제품, 활용 장면, 추천 내용 | 제품 이해 후 신뢰 근거를 이어서 노출 |
| [Fishwife](https://eatfishwife.com/) | 원료·활용 설명과 공급자 이야기 | 유용한 정보는 바로 보여주되 조작 UI는 추가하지 않음 |
| [bibigo](https://www.bibigo.com/kr) | 이야기·제품·파트너십·문의 | 글로벌 식품 브랜드의 핵심 탐색 목적을 유지 |
| [Kikkoman](https://www.kikkoman.com/en/) | 요리 활용·식문화·생산 품질 | 소비자 활용과 기업 신뢰를 연결하되 기업 정보 과밀은 피함 |

HEATONIST도 조회했으나 이번 채택 근거로 충분히 검토하지 않아 위 비교에서 제외했다. 다른 브랜드의 문구·사진·로고는 복사하지 않았다.

## 검증과 범위

- 이 작업 중 한국어·스페인어·영어와 390px·1280px 화면에서 변경 구성을 직접 확인했다. 뷰포트 설정 직후 1280px에 머문 탭은 모바일 검증으로 세지 않았고, 마지막 기본 크기 복원 후 실제 390px을 다시 확인했다.
- 제품·음식·추천사·FAQ를 조작 없이 읽는 배치를 확인했다. 응원 폼 첫 입력란을 가리던 헤더 겹침은 수정 후 데스크톱과 390px 모바일에서 직접 확인했다.
- 제품 상세와 응원·문의 링크를 실제로 클릭해 목적지를 확인했다. 폼은 제출하지 않았다.
- 본문 객체는 index.html 및 products.html의 KR/ES/EN 여섯 비교에서 Git HEAD와 동일했다. 응원 버튼은 기존에 쓰던 행동 문구로 정리했다.
- 다국어 18페이지 생성, 분석 회귀 14개, 타입 검사, 스크립트 문법 및 diff 공백 검사를 수행했다.
- 체험단 별점·후기 데이터는 빈 상태다. 기존 응원 메시지의 샘플 합산 설정은 별개이며 이번 디자인 작업에서 실적 데이터로 검증하거나 변경하지 않았다.
- 커밋·푸시·공개 배포는 수행하지 않았다.
