# MOKDA 홈페이지 타이포그래피 규정

적용일: 2026-10-10. 한국어·스페인어·영어 공개 홈페이지 전체에 적용한다. 이 문서는 홈페이지의 글꼴, 크기, 굵기, 자간, 행간에 대한 운영 기준이다. 신규 페이지와 기존 페이지 수정에도 같은 기준을 사용한다.

## 기본 원칙

- 같은 역할의 글자는 페이지가 바뀌어도 같은 기준을 따른다. 홈의 캠페인 문구, 제품명, 기사 제목은 각각 별도의 위계를 갖는다.
- 카드에 내용을 넣기 위해 글씨를 줄이지 않는다. 필요한 경우 카드 너비와 여백, 줄바꿈을 함께 조정한다.
- 모바일에서 일반 본문과 입력값은 16px을 유지한다. 짧은 카드 후기와 보조 정보에는 아래 역할별 기준을 적용한다.
- 한국어는 Noto Sans KR, 스페인어·영어는 Noto Sans를 본문 기본 서체로 사용한다. 시스템 글꼴은 로딩 실패 시의 대체 글꼴이다.
- 한국어 문장에 라틴 전용 display 클래스를 적용하지 않는다. K-PEÑO, Para Carnes, Salsa Coreana 등 라틴 제품명은 언어에 관계없이 라틴 display를 사용할 수 있다.
- 메인 페이지 섹션 제목과 짧은 소개는 가운데 정렬한다. 기사·FAQ·폼의 읽기 영역은 해당 페이지의 확정된 정렬을 유지한다.
- 브랜드 색, 문구, 사진, 기능, 메뉴 구조를 타이포그래피 정리 과정에서 임의로 교체하지 않는다.

## 서체와 굵기

| 역할 | 서체 | 굵기 |
|---|---|---|
| 한국어 본문·UI | Noto Sans KR → Noto Sans → sans-serif | 본문 400, 보통 강조 500–600, 버튼·질문 700 |
| 스페인어·영어 본문·UI | Noto Sans → Noto Sans KR → sans-serif | 본문 400, 보통 강조 500–600, 버튼·질문 700 |
| 캠페인·제품명·뉴스의 라틴 display | Archivo Black → Noto Sans → Noto Sans KR → sans-serif | 400. 원래 굵은 서체이므로 900으로 별도 요청하지 않는다 |
| 한국어 display | Noto Sans KR → Noto Sans → sans-serif | 800 |
| 소개 페이지의 서사 제목 | Noto Sans/Noto Sans KR | 800. 현재의 차분한 제목 디자인을 유지한다 |
| 모바일 메뉴의 짧은 MENU·번호 | Bebas Neue | 400. 공통 헤더에서 같은 값을 사용한다 |

원본 HTML의 기존 font-black/font-extrabold 보정 규칙은 넓게 재작성하지 않는다. 실제 역할의 클래스와 공통 컴포넌트에서 굵기를 명시해 페이지별 상속 차이를 막는다.

장식용 별점 기호·아이콘과 내부 미리보기용 sample 표시는 본문 최소 크기의 대상이 아니다. 운영 중인 후기 문장은 예외가 아니다.

헤더의 메뉴 제목·하위 링크는 `site-header.js`의 역할별 반응형 값을 사용한다. 모바일 메뉴 제목은 `clamp(28px, 8vw, 42px)`과 라틴 1.12·한국어 1.18 행간을 사용하고, 하위 링크는 14px/1.35이다. 일반 링크 규칙으로 메뉴 전체를 덮지 않는다. 운영체제가 그리는 네이티브 select는 16px을 지정하되, 브라우저가 행간을 normal로 계산할 수 있다.

## 제목의 위계

- 기존 홈 첫 화면의 캠페인 문구와 제품명 크기를 유지한다. 모든 제목을 동일한 px로 만들지 않는다.
- 짧은 라틴 제품명은 기존 조형을 유지한다. 홈·제품 목록의 제품명은 .88, 제품 상세의 제품명은 1.08 행간을 사용하는 명시적 예외다. 제품 설명과 문의 제목은 일반 제목 기준을 적용한다.
- 일반 섹션 제목은 현재의 반응형 크기를 사용하되 같은 역할 안에서 크기·행간을 일치시킨다. 일반 display의 행간은 라틴 1.12, 한국어 1.18을 기준으로 한다.
- 홈 첫 화면의 한국어 캠페인은 기존 1.08 행간을 유지한다. 홈 역사 미리보기 제목은 두 언어 모두 현재 1.16 행간을 사용한다.
- 소개 페이지는 페이지 제목과 섹션 제목을 구분한다. 서사 제목의 Noto 800, 일반 섹션 제목의 1.18 행간을 유지한다. 홈 소식 미리보기 제목도 기존 Noto 800을 사용하며, 한국어 1.18·라틴 1.12 행간을 적용한다.
- FAQ 페이지 제목은 세 언어 모두 `clamp(2.4rem, 4.7vw, 4rem)`을 사용한다. 모바일은 기존 `clamp(2rem, 7.8vw, 2.5rem)`. 한국어 1.18, 라틴 1.12 행간을 사용한다.
- 뉴스 기사 제목은 기존 데스크톱 46px/1.25, 태블릿 30px/1.25, 모바일 28px/1.3을 유지한다. 긴 제목은 줄바꿈으로 처리한다.
- display 자간은 보통 −.02~−.035em, 서사 제목은 기존 −.04em까지 허용한다. 본문과 출처 문장에는 display 자간이나 작은 영문 라벨의 넓은 자간을 적용하지 않는다.

## 구현 위치와 관리 방법

- 우측 하단 채팅 상담은 `styles/site-help.css`에서 관리한다. 창 제목은 18px/700/1.4, 대화 말풍선은 16px/400/1.75, 입력값은 16px/1.5이다. 주제·빠른 질문 버튼은 좁은 대화창의 탐색 UI로 14px/600/1.5를 사용하고, 담당자 문의는 14px/700/1.5를 적용한다. 자동 응답 표시는 12px, 부제·새 대화는 13px의 보조 위계다. 버튼은 44px 이상, 입력·전송 버튼은 48px 이상으로 유지한다. 원형 실행 버튼은 데스크톱 60px, 모바일 56px이다. 페이지를 가리지 않는 대화창 안에서 메시지만 스크롤하고 하단 입력·상담 버튼은 계속 보이게 한다.

- 제품 목록의 두 소개 패널은 `styles/product-layout.css`에서 관리한다. 콘텐츠 너비는 최대 1440px, 768px 이상 행의 최소 높이는 `clamp(560px, 50vw, 720px)`, 사진 높이는 최대 720px로 제한한다. 긴 문구가 있으면 행 높이는 늘어날 수 있도록 고정 height를 사용하지 않는다. 사진은 배경색과 연결하고 별도 테두리·카드 여백을 만들지 않으며, 병의 뚜껑과 바닥이 보이는 구도를 확인한다. 텍스트는 가운데 정렬과 최대 32rem 너비를 유지한다.
- 공통 토큰: `styles/site-typography.css`의 `--mokda-font-*`, `--mokda-type-*`, `--mokda-leading-*`, `--mokda-tracking-*`.
- 헤더·푸터: `site-header.js`, `site-footer.js`. 공통 컴포넌트 안에서 서체·굵기·행간·자간을 명시한다.
- 역할별 세부 규칙: home/product/about/news CSS. 공통 토큰을 사용하는 것이 우선이며, 문서에 적힌 역할 예외만 별도 값으로 관리한다.
- 원본 정적 HTML·공통 스크립트를 수정한 뒤 `npm run generate:i18n`으로 `/ko`, `/es`, `/en`을 생성한다. 생성 파일만 직접 수정하지 않는다.
- 규정 변경은 이 파일을 갱신한다. 점검 기록은 `output/typography-audit`에 두며 운영 규정의 사본을 만들지 않는다.
- 스페인어 제품 상세의 원본 이미지 안 글자는 CSS로 수정할 수 없다. 이미지 교체·편집은 별도 범위로 처리한다.

## 완료 기준

1. 세 언어와 390px·768px·1440px 화면에서 실제 적용된 font-family, font-size, font-weight, letter-spacing, line-height를 확인한다.
2. 같은 헤더·푸터의 값, 한국어 클래스 전환, 폼과 검색 입력 크기를 비교한다.
3. 긴 뉴스 분류·날짜는 작은 화면에서 줄바꿈을 허용하며 서로 겹치거나 잘리지 않는다.
4. 제목 줄바꿈, 후기 카드, 사진 비율, 가로 목록·갤러리·컨베이어를 실제 화면으로 확인한다.
5. 페이지 가로 스크롤·글자 잘림·콘솔 오류를 확인한다. 실제 문의는 제출하지 않는다.
6. 다국어 생성, 프로젝트 필수 검사와 변경 관련 회귀 검사를 통과하고 `git diff`로 범위를 검토한다.

홈페이지 수정은 대표님의 상시 지시(2026-10-10)에 따라 검증 후 커밋·푸시·공개 배포와 운영 확인까지 진행한다. 특정 작업의 검토용·배포 제외 지시가 있으면 그 최신 지시를 따른다.
